# 層の割り当て

振る舞いをどの層で確かめるか迷ったとき、既存のテストの重なりを整理するときに読む。

## 下の層から考える

同じ失敗を再現できる最も下の層を持ち主にする、という原則はrepositoryのテスト戦略が持つ。この資料は、Reactの振る舞いをどの層へ当てるかだけを書く。

純粋な判断（状態遷移、値の変換、URLやformのschema、結果型から表示の種類への写し）は、単体テストの持ち物である。全分岐と境界値をここで網羅する。表示から切り出していない判断は、まず切り出せるかを考える。

表示だけを担う部品の有限の状態（空、読み込み中、失敗、成功、権限なし）、見た目の違い、一つの操作、accessibilityは、storyとbrowser testの持ち物である。storyは、Serverが渡す認可済みのDTOを模したpropsで状態を作り、tokenや生の認可の情報を含めない。待機、失敗、競合、空の状態を、利用者が区別できる状態として示す。

Server Functionと、Serverでreadを持つ部品の、入力の検証、認可、成功、予測できる失敗、遷移先は、Serverの境界を直接呼ぶテストの持ち物である。認可の分岐（未認証、他人の資源、権限なし）をここで網羅し、Client側で繰り返さない。scopeを変えたreadが混ざらないこと（別の利用者の値が見えないこと）も、ここで固定する。

Actionを持つClient部品の、送信中の表示、結果の反映、失敗からの回復、入力の誤りの関連付けは、部品のテストの持ち物である。Server Functionの中身はこの層で複製しない。

実際の認証、redirect、backend、データベースをまたぐ主要な経路は、E2Eの持ち物である。どの経路を残すかはrepositoryのテスト戦略が決め、この層では業務の境界値を網羅しない。

## 道具は案件が選ぶ

層の名前と道具の対応は、repositoryが選ぶ。よくある対応は、単体テストがVitest、storyとbrowser testがStorybookとそのtest runner、部品のテストがTesting Library、E2EがPlaywright、外部通信の差し替えがMSWである。道具が違っても、層の持ち物は変わらない。

## 判断例（図書館の貸出）

貸出の結果型から表示の文を選ぶ関数は、単体テストで `borrowed`、`overdue`、`loan_limit`、未知の種類（throwする）の四つを確かめる。「借りている本」の一覧の部品は、storyで、貸出が無い、延滞がある、の状態とaccessibilityを確かめる。貸出のServer Functionは、利用者本人として借りられ、延滞があれば拒まれ、未認証ならredirectすることを、Serverの境界を直接呼ぶテストで確かめる。「借りる」buttonを持つClient部品は、送信中にbuttonが押せなくなり、拒まれたら理由が表示され、もう一度押せることを部品のテストで確かめる。ログインして本を借り、「借りている本」に現れるまでの一本だけをE2Eに残す。
