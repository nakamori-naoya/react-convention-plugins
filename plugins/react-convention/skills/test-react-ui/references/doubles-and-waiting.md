# 差し替えと待機

どの境界を差し替えてよいかは、repository のテスト戦略が決める。この資料は、React のテストでそれをどの仕組みで差し替え、非同期の結果をどう待つかを書く。

## 差し替えの仕組み

外部との通信は、HTTP の契約を経由して差し替える道具（MSW など）を優先する。要求と応答の形をテストが確かめられるからである。認証の SDK のように、テストの環境で初期化できないものは、SDK の最小の面だけを置き換える。時刻に依る表示（返却期限まであと何日）は、時刻の源を差し替えられる形にしてから確かめる。描画中に現在時刻を直接読むと、実行した日で結果が変わる。

実行基盤が用意する module のうち、テストの環境では読み込めないものは、挙動を足さない空の置き換えを一か所に集めて使う。

手で書く偽物は、差し替えてよい境界に限り、本物の型と、成功、失敗、空の値を表す契約の fixture として一か所に置く。呼び出しを観測するだけの関数（`vi.fn` など）は、外部の境界へ渡す callback の観測にだけ使う。本物を保ったまま観測する `spyOn` は、後片付けで必ず元に戻す。

`vi.mock` や decorator で自分の部品、hook、Server Function、Provider の module を置き換えない。置き換えた部分の本物が一度も確かめられないからである。Provider を使う View の story では、本番の公開 Context 型に一致する状態（認証済み、待機、空、失敗）を parameter で渡してよい。そのとき Provider 自身の振る舞いは、本物の Provider を使うテストで別に確かめる。

## 待機

表示が現れる、button が押せるようになる、応答が返る、という条件を、待機付きの問い合わせ（`findBy...`、`waitFor` に条件を渡す形）で待つ。固定の sleep が要るように見えたら、テストの側で隠さず報告する。
