# 差し替えと待機

テストで何かを差し替えたくなったとき、非同期の結果を待つテストを書くときに読む。

## 差し替えを三つに分ける

テストで差し替える対象は、三つに分けて扱う。

一つ目は、テストの環境に存在しないmoduleである。実行基盤が用意するmoduleで、テストの環境では読み込めないものがこれに当たる。挙動を足さない空の置き換えを、一か所に集めて使う。

二つ目は、実行時に外部と通信するか、外部のSDKを呼ぶ境界である。認証のSDK、backendへの通信、ブラウザに無いAPIがこれに当たる。ここだけは差し替えてよい。外部との通信は、HTTPの契約を経由して差し替える道具を優先し、要求と応答の形をテストが確かめられるようにする。SDKを初期化できない環境では、SDKの最小の面だけを置き換える。

三つ目は、自分のコードである。部品、hook、Server Function、Providerのmodule、状態遷移の関数がこれに当たる。これは差し替えない。自分のコードを `vi.mock` やdecoratorで置き換えると、置き換えた部分の本物が一度も確かめられない。Providerを使うViewのstoryでは、本番の公開Context型に一致する状態（認証済み、待機、空、失敗）をparameterで渡してよいが、Provider自身の振る舞いは本物のProviderを使うテストで別に確かめる。

手で書く偽物は、二つ目の境界に限り、本物の型と、成功、失敗、空の値を表す契約のfixtureとして一か所に置く。呼び出しを観測するだけの関数は、外部の境界へ渡すcallbackの観測にだけ使う。本物を保ったまま観測する `spyOn` は、後片付けで必ず元に戻す。

## 待機

テストは、固定の時間ではなく、観測できる条件になるまでを期限付きで待つ。表示が現れる、buttonが押せるようになる、応答が返る、という条件を、待機付きの問い合わせ（`findBy...`、`waitFor` に条件を渡す形）で待つ。固定のsleepは、待つべき条件が観測できないか、時刻の源を制御できないことの症状であり、テストの側で隠さず報告する。

時刻に依る表示（返却期限まであと何日）は、時刻の源を差し替えられる形にしてから確かめる。描画中に現在時刻を直接読むと、テストが実行した日によって結果が変わる。
