# 差し替えと待機

テストで何かを差し替えたくなったとき、非同期の結果を待つテストを書くときに読む。

## 差し替えてよいもの、よくないもの

差し替えてよいのは、テストの環境に無いmodule、外部と通信するかSDKを呼ぶ境界（ブラウザに無いAPIを含む）、時刻の源の三つだけである。自分のコードは差し替えない。

テストの環境に存在しないmoduleは、実行基盤が用意するmoduleで、テストの環境では読み込めないものである。挙動を足さない空の置き換えを、一か所に集めて使う。

外部と通信するか外部のSDKを呼ぶ境界は、認証のSDK、backendへの通信、ブラウザに無いAPIである。外部との通信は、HTTPの契約を経由して差し替える道具を優先し、要求と応答の形をテストが確かめられるようにする。SDKを初期化できない環境では、SDKの最小の面だけを置き換える。

時刻の源は、描画や判断が現在時刻を読む箇所である。時刻に依る表示を確かめるときだけ差し替える。

自分のコード（部品、hook、Server Function、Providerのmodule、状態遷移の関数）は差し替えない。自分のコードを `vi.mock` やdecoratorで置き換えると、置き換えた部分の本物が一度も確かめられない。Providerを使うViewのstoryでは、本番の公開Context型に一致する状態（認証済み、待機、空、失敗）をparameterで渡してよいが、Provider自身の振る舞いは本物のProviderを使うテストで別に確かめる。

手で書く偽物は、外部の境界に限り、本物の型と、成功、失敗、空の値を表す契約のfixtureとして一か所に置く。呼び出しを観測するだけの関数は、外部の境界へ渡すcallbackの観測にだけ使う。本物を保ったまま観測する `spyOn` は、後片付けで必ず元に戻す。

## 待機

待機の原則（固定の時間ではなく、観測できる条件を期限付きで待つ）は、repositoryのテスト戦略が持つ。Reactのテストでは、表示が現れる、buttonが押せるようになる、応答が返る、という条件を、待機付きの問い合わせ（`findBy...`、`waitFor` に条件を渡す形）で待つ。

時刻に依る表示（返却期限まであと何日）は、時刻の源を差し替えられる形にしてから確かめる。描画中に現在時刻を直接読むと、テストが実行した日によって結果が変わる。
