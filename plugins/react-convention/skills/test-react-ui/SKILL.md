# test-react-ui

React の画面、Server Function、部品の振る舞いを、それを確かめられる最も安い一つの層へ割り当て、その層の形でテストを書く。

## 本質

一つの振る舞いを最も小さい層で確かめること、差し替えてよい境界、固定の時間ではなく観測できる条件を待つことは、repository のテスト戦略が決める。このskillは、それを React のテストへ当てる形だけを持つ。

テストは、利用者が観測できるもの（role、accessible name、表示された状態、外へ渡した callback の引数）で確かめ、props の呼び出し順や内部の state に依らない。外部の境界への呼び出しの回数だけを合格の条件にしない。

どの層に何を割り当てるかは [層の割り当て](references/layer-assignment.md) を、何をどの仕組みで差し替え、どう待つかは [差し替えと待機](references/doubles-and-waiting.md) を読む。

## テストのために実装を曲げない

テストのためだけに内部の関数を export したり、テスト専用の分岐や props を本番の部品に足したりしない。内部にしか無いものを確かめたくなったら、公開している振る舞いから確かめるか、その判断を純粋な関数として切り出せるかを考える。

## 進め方と止まるとき

対象 repository の AGENTS.md、package.json、テストの設定、テスト戦略の資料と、任意の `references` を読み、使うテストの道具と完了判定の command を確かめる。対象の振る舞いを、判断、表示の状態、Server の境界の分岐、Action の状態、主要な経路に分けて層へ割り当て、既存のテストと重なるものはどちらに残すかを決めてから書く。書いたら完了判定の command を実行し、story や表示だけの部品を変えたなら browser test も実行する。認証や更新の経路を変えたときは、外部の境界も差し替えない E2E を repository の決めた場所で走らせる。

このskillはコードを変えるので、欠けた情報がテストを変えるときは推測で埋めずに止まり、何が分からないかと提案を返す。確かめるべき振る舞い（期待する表示、失敗の種類、認可の規則）が資料からもコードからも決まらないとき、自分のコードを差し替えなければ書けない構造のとき（差し替えずに書ける形への変更を提案する）がこれに当たる。

書いたテストのファイル、振る舞いごとに割り当てた層と理由、差し替えた境界、消した重複、完了判定の結果、止まった点と提案を報告する。
